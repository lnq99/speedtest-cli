# План и проектные решения / Plan & Design Decisions

## Задача

Консольный скрипт, который:
1. принимает адрес (URL), к которому стучаться;
2. делает к нему **10 последовательных** запросов и дожидается полного ответа на
   каждый;
3. считает среднее время запроса и общий объём скачанных данных;
4. печатает скорость скачивания (единицы на наш выбор, указаны в README).

## Решения / Decisions

**Язык: Python 3 + `requests`.** Простая и читаемая реализация; `requests.get()`
с чтением `.content` гарантирует полное скачивание тела ответа. Единственная
зависимость.

**Последовательно, не параллельно.** Требование задачи — 10 запросов подряд, с
ожиданием полного ответа на каждый. Никакой конкурентности.

**Единицы — MB/s (десятичные мегабайты).** 1 MB = 1 000 000 байт. Так принято
указывать скорость передачи данных, и число легко сопоставить с привычными
«мегабитами/мегабайтами в секунду». В README явно оговорено отличие от MiB.

**Скорость = суммарный объём / суммарное время.** Это корректная совокупная
пропускная способность. Усреднять скорости отдельных запросов было бы
статистически неверно (короткие быстрые запросы перекосили бы среднее).

**Обработка ошибок — fail fast.** При сетевой ошибке/плохом URL печатаем
понятное сообщение в stderr и выходим с ненулевым кодом. Для разминочной задачи
ретраи и сложная логика не нужны.

**Гибкость через флаги.** `-n/--requests` (по умолчанию 10) и `--timeout`
(по умолчанию 30 с) — чтобы скрипт было удобно проверять, сохраняя поведение по
умолчанию из условия.

## Вне рамок / Out of scope (YAGNI)

Upload-скорость, латентность/джиттер, прогресс-бары, конкурентность, ретраи,
вывод в JSON. Всё это не требуется условием и усложнило бы «лёгкое тестовое».
