# Архитектура / How the code works

Весь код — в `speedtest.py`, четыре функции с одной ответственностью каждая.

```
main()                 # ловит ошибки, код выхода 0/1
 ├─ parse_args()       # argparse: url, -n, --timeout
 ├─ measure()          # N последовательных запросов, накопление байт/времени
 │   └─ download_once()  # один GET + полное чтение .content, замер времени
 └─ format_report()    # avg_time и speed → текстовый отчёт
```

## Ключевые детали

- **`download_once`** засекает `time.perf_counter()` **до** запроса и **после**
  чтения `response.content` — значит, время покрывает всю загрузку, а не только
  время до первого байта. `raise_for_status()` переводит 4xx/5xx в исключения.
- **`measure`** вызывает `download_once` ровно `n` раз последовательно (следующий
  запрос — только после полного завершения предыдущего).
- **`format_report`** считает `avg_time = total_time / n` и
  `speed = (total_bytes / 10⁶) / total_time` (MB/s), с защитой от деления на ноль.

Скорость — совокупная пропускная способность по всем запросам, а не среднее
скоростей отдельных запросов.

## Тесты

`tests/test_speedtest.py` (pytest), три уровня: юнит чистых функций
(`format_report`, `parse_args`); мок-тест цикла `measure()` (ровно N запросов,
корректная сумма байт); герметичная интеграция против локального `http.server`.
